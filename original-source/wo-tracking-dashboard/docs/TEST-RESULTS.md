# ผลการทดสอบจริง

วันที่จัดทำ 21 ตุลาคม 2026 สภาพแวดล้อม Linux, Node.js 24.19.0, npm 11.9.0 ใช้ package-lock.json ที่ส่งมอบ รายงานนี้แยกการทดสอบโค้ดออกจากสิ่งที่ยังไม่มีสภาพแวดล้อมจริงให้ตรวจ

## ผ่านแล้ว

| กลุ่ม | ผลที่ตรวจจริง |
|---|---|
| ติดตั้ง Dependencies | npm install สำเร็จ มี package-lock.json |
| Syntax และ Build | npm run check ผ่าน Vite Production Build สำเร็จ |
| Backend / กฎ / HTTP / SQLite | Node test ผ่าน 23 กรณี |
| หน้าจอและการกดใช้งาน | React Testing Library + jsdom ผ่าน 13 กรณี |
| Startup จริง | เปิด backend/src/server.js ด้วย Node และเรียก Health / Dashboard ผ่าน HTTP |
| Frontend ที่ Build แล้ว | Server ส่ง index.html และ JavaScript asset ผ่าน HTTP ได้ |
| คำสั่งพัฒนาจริง | npm run dev เปิดทั้ง Express และ Vite, localhost:5173 ส่ง HTML ได้, /api/health ผ่าน proxy ได้ และแปลง JSX/Tailwind ผ่าน |
| Restart จริง | บันทึกหมายเหตุ Demo หยุดโปรเซส Server เปิดใหม่ แล้วอ่านหมายเหตุเดิมได้ |
| Backup | npm run backup สร้างชุดสำรอง demo.sqlite และ real.sqlite |
| แม่แบบ | สร้าง XLSX ตรวจภาพของทั้ง 2 แท็บ และนำกลับเข้าโปรแกรมจริงได้ 4 แถว วันที่ 2026-10-16 และ TRUE/FALSE อ่านถูกต้อง |
| Dependency audit | npm audit รายงาน 0 ช่องโหว่ ณ เวลาตรวจ ไม่ใช่การรับรองความปลอดภัยของโค้ดทั้งหมด |
| ตรวจแพ็กเกจ ZIP | แตก ZIP ไปโฟลเดอร์ใหม่ ติดตั้งด้วย npm ci --prefer-offline สำเร็จ และ npm test / npm run smoke ผ่านทั้งเปิดเว็บ/API, Restart, ดาวน์โหลดแม่แบบ และ Backup |

Backend เดิม 18 กรณีครอบคลุม ACCEPT/REJECT/DIRECT, DIRECT ที่ยังไม่ยืนยัน, ไม่มีผล, Model ไม่ตรง, ไม่มีหลักฐาน, ผลกำกวม/ปฏิเสธ, Hash การยืนยันเก่า, ผลรวมการ์ด, วันรอประเทศไทย, Demo 25 รายการ/5 Invoice, SAP ซ้ำหลาย Invoice, ข้อมูลซ้ำ/ไม่ครบ, วันที่/Boolean ไม่ถูกต้อง, หมายเหตุและประวัติ, process ใหม่อ่านข้อมูลเก่าได้, WO ที่คนยืนยันไม่ถูกนำไปใช้อีกรายการ, Preview/Commit และการแยกโหมด, การยืนยัน/ยกเลิก, Export XLSX ตามตัวกรอง, Error เมื่อยังไม่มี Credentials, Preview เก่าถูกบล็อก และการอ่าน XLSX ทั้งแบบ ExcelJS และแม่แบบที่ส่งมอบ

Frontend เดิม 10 กรณีครอบคลุมการ์ดรวม, เลือก Invoice และการ์ดเฉพาะใบ, ค้นหา/กรอง Invoice, ค้นหา/กรอง/แบ่งหน้ารายการ, โหมดจริงว่าง, Preview ผิดรูปแบบห้ามยืนยัน, Preview ที่ผ่านเรียก Commit, กรองรายการติดตามและส่งออก, บันทึกหมายเหตุ, Copy LINE, บันทึก Spreadsheet ID และการส่งข้อมูลยืนยันพร้อม Hash ต้นทาง

เพิ่มสำหรับ PDF 8 กรณี (Backend 5 + Frontend 3): อ่าน PDF จริง 2 หน้า 4 รายการ, Invoice/วันที่/Ref./SAP PO./SAP NO./Description ต่อบรรทัด, ปฏิเสธไฟล์ปลอมและไฟล์เสีย, หน้าที่ไม่มีข้อความให้กรอกเอง, ไม่เดารหัสจากตัวเลขนอกตาราง, หัวตารางสองบรรทัด, คง QC/WO/หมายเหตุ/การยืนยันเมื่อนำเข้า PDF ซ้ำ, บล็อก Ref. จับคู่กำกวม, Preview ยังไม่บันทึก, แยกโหมด, ตรวจเงื่อนไขยืนยันจากคน, แก้ข้อมูลก่อนนำเข้า, ปฏิเสธเกิน 10 MB, เปิดฐานข้อมูลใหม่ยังอ่านรายการ PDF เดิมได้, เพิ่ม/ลบแถวเอง, และการแก้ร่าง/เลือกไฟล์ใหม่ยกเลิก Preview เก่า

รวม 36 กรณีผ่าน ไม่มีกรณีล้มเหลว ตรวจ PDF ตัวอย่างด้วยการ Render ภาพหน้าแรกแล้ว ไม่ใช่การทดสอบ PDF ของบริษัททุกแบบ ภาพสแกนยังไม่มี OCR

ค่า Demo ตั้งต้นที่ตรวจอิสระ: Invoice 5, รายการ 25 = เปิดแล้ว 12 + รอเปิด 4 + รอผล 6 + ต้องตรวจสอบ 3 มี Invoice เปิดครบ 2 ใบ

## ยังไม่ผ่านการตรวจในสภาพแวดล้อมจริง

- ไม่มี Credentials จึงยังไม่ได้ทดสอบ OAuth/สิทธิ์/อ่าน Google Sheets ของบริษัทจริง ทดสอบแล้วเฉพาะ API ตั้งค่าและกรณีไม่มี Key
- ยังไม่ได้เปิดหน้าจอจริงใน Chrome/Safari และไม่ได้จับภาพ Responsive จริง jsdom ไม่มีการจัดหน้าตามพิกเซล จึงไม่ใช้ผล DOM เป็นหลักฐานยืนยันความเหมือนภาพอ้างอิง
- ยังไม่ได้ติดตั้งและเปิดบน Windows/macOS จริง ให้ทำตาม docs/TESTING.md บนเครื่องผู้ใช้
- ยังไม่ได้ Load test งานจำนวนมากหรือเปิดใช้หลายผู้ใช้ และไม่มีการเชื่อม SAP/LINE โดยตรง

ไม่มีการ Deploy เว็บไซต์ ไม่มีการส่งข้อความให้ใคร และใช้ข้อมูลสมมติทั้งหมดระหว่างทดสอบ
