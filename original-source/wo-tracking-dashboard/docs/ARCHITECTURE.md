# โครงสร้างระบบและกฎ

React + Vite เป็นหน้าจอ Tailwind CSS จัดรูปแบบ Lucide เป็นไอคอน Node.js + Express ให้บริการ API และ SQLite เก็บข้อมูล ใช้ SQLite ที่มากับ Node 24 เพื่อไม่ต้องติดตั้งโปรแกรม Database แยกหรือ Compile native module

## ขั้นตอนข้อมูล

ไฟล์ / Google Sheets > ตรวจหัวคอลัมน์และชนิดข้อมูล > ตรวจรหัสซ้ำและการจับคู่ > Preview > ยืนยันนำเข้า > SQLite > ประเมินสถานะ > แสดง Summary / รายการ / Excel

Google Sheets ใช้ Google Auth Library ขอ Token ฝั่ง Backend แล้วอ่าน Sheets API v4 ส่วน Frontend เห็นเพียงสถานะว่าพบไฟล์ Credentials หรือไม่ ไม่ได้รับ Private Key

## กฎสถานะ

| เงื่อนไข | ผล |
|---|---|
| ACCEPT | ต้องเปิด STK+CTN_CHANGE CODE |
| REJECT | ต้องเปิด Inspection_Assembly |
| DIRECT ยืนยันพร้อมชื่อและอ้างอิง | ต้องเปิด DIRECT |
| DIRECT ยังไม่ยืนยัน | รอผล ไม่กำหนด Model อัตโนมัติ |
| ไม่มี QC / DIRECT | รอผล ไม่กำหนด Model |
| มีผลแล้ว ไม่มีเลข WO และไม่มีข้อมูล WO ที่ขัดแย้ง | รอเปิด WO |
| เลข WO + Model ตรง + wo_verified + หลักฐาน WO | เปิดแล้ว |
| เลข WO แต่ Model ไม่ตรง / ไม่มี Model / ไม่มีหลักฐาน | ต้องตรวจสอบ |
| มี WO แต่ยังไม่มี QC | ต้องตรวจสอบ |
| ผล QC กำกวม / หลายผล / ต้นทางเปลี่ยนหลังยืนยัน | ต้องตรวจสอบ |

ระบบอ่านเฉพาะคำที่รองรับ ได้แก่ ACCEPT, ACCEPTED, ACC.LOT, ผลผ่าน, REJECT, REJECTED, DIRECT กรณีผลขัดแย้งหรือข้อความปฏิเสธบางรูปแบบ จะส่งให้คนตรวจ ไม่ใช้ AI เดา คำใหม่ที่ยังไม่รองรับให้ยืนยันด้วยคน หรือเพิ่มกฎและทดสอบก่อนใช้งาน

## หน่วยของ Summary

PACKING LIST นับ Invoice ที่ไม่ซ้ำ อีก 3 การ์ดนับรายการติดตามทั้งหมดที่มีสถานะสำเร็จ / รอเปิด / รอผล ส่วนต้องตรวจสอบแยกเป็นข้อความเตือนเพื่อคงการ์ด 4 ใบตามแบบ

จำนวนรายการทั้งหมด = เปิดแล้ว + รอเปิด WO + รอผล + ต้องตรวจสอบ การ์ดของ Invoice ใช้เฉพาะรายการ Invoice นั้น หากมีต้องตรวจสอบจะแสดงจำนวนเพิ่มใต้การ์ด

Invoice เปิดครบต่อเมื่อมีรายการและทุกรายการเปิดแล้ว หากมีข้อผิดปกติสถานะ Invoice จะเป็นต้องตรวจสอบก่อน หากมีเปิดแล้วบางส่วนเป็นเปิดบางส่วน และที่เหลือเป็นยังไม่เปิด WO

วันเริ่มรอผลใช้ received_date วันเริ่มรอเปิด WO ใช้ qc_date ถ้าไม่มีวันที่ไม่แทนด้วยวันที่นำเข้า คำนวณวันปฏิทินตาม Asia/Bangkok ไม่หักวันหยุดและไม่เป็น SLA วันทำงาน

## ฐานข้อมูล

| ตาราง | เก็บอะไร |
|---|---|
| schema_migrations | รุ่น Schema |
| invoices | เลข Invoice และวันที่/เจ้าของ |
| invoice_items | รหัสภายในจาก SHA-256 ของ Invoice + item_ref, รหัสสินค้า, ต้นทางและ Hash |
| qc_results | ผล QC ล่าสุดและหลักฐาน DIRECT |
| wo_records | WO ล่าสุดของรายการ |
| user_confirmations | ข้อมูลที่คนตรวจและยืนยัน พร้อม Hash ต้นทางขณะยืนยัน |
| follow_up_notes | หมายเหตุ ผู้บันทึก และวันที่ติดตาม |
| sync_history | ประวัตินำเข้า/Sync สำเร็จและข้อผิดพลาดเชื่อมชีต |
| audit_history | ข้อมูลก่อน/หลัง แหล่งข้อมูล เวลา และผู้ทำรายการ |
| settings | Spreadsheet ID และ Range แยกตามโหมด |

ใช้ WAL และ Transaction ในการนำเข้า Migration 001 รันอัตโนมัติแบบสร้างเมื่อยังไม่มี เมื่อพัฒนารุ่นถัดไปต้องเพิ่ม Migration ใหม่และทดสอบข้อมูลเก่าก่อน ไม่มี SQL ที่ลบฐานข้อมูลเมื่อเปิด Server

## ข้อมูลเปลี่ยนหลังยืนยัน

ทุกแถวต้นทางมี Hash การยืนยันด้วยคนบันทึก Hash ขณะนั้น หาก Refresh ได้ข้อมูลเหมือนเดิมจะใช้การยืนยันต่อ หากเปลี่ยนแม้เพียง Description หรือหมายเหตุต้นทาง ระบบถือว่าต้องตรวจใหม่ การยืนยันเดิมไม่ถูกลบ แต่ไม่ถูกใช้สรุปว่าสำเร็จโดยอัตโนมัติ ผู้ใช้ดูประวัติแล้วตรวจ/ยืนยันใหม่หรือยกเลิกการยืนยันเพื่อใช้ต้นทาง

## API หลัก

ทุก API เลือกโหมดผ่าน header `x-data-mode: demo` หรือ `real` ถ้าไม่ระบุใช้ demo

| Method / Path | หน้าที่ |
|---|---|
| GET /api/health | ตรวจ Server |
| GET /api/dashboard | Summary รวมและ Invoice |
| GET /api/items | รายการพร้อมสถานะ |
| GET /api/items/:id | รายละเอียด หมายเหตุ และประวัติ |
| POST /api/items/:id/notes | เพิ่มหมายเหตุ |
| POST /api/items/:id/confirm | ยืนยันข้อมูลพร้อมชื่อ เหตุผล และ source_hash |
| DELETE /api/items/:id/confirm | ยกเลิกการยืนยัน มี Audit |
| POST /api/import/preview | อัปโหลด multipart field ชื่อ file |
| POST /api/import/commit | ยืนยัน token จาก Preview |
| GET /api/settings | การตั้งค่าที่ไม่เป็นความลับ |
| PUT /api/settings | ตั้ง Spreadsheet ID / Range |
| POST /api/sheets/preview | อ่านชีตมา Preview เฉพาะโหมดจริง |
| GET /api/history | ประวัติตามโหมด |
| GET /api/export | Excel รายการติดตามหรือสรุป Invoice |
| GET /api/template | ดาวน์โหลดแม่แบบ |

## ขอบเขตความปลอดภัย

Server ฟังเฉพาะ 127.0.0.1 ปฏิเสธ Host และ Origin ภายนอกตามขอบเขต localhost ไม่เปิด CORS สำหรับเว็บภายนอก ใช้ parameterized SQL และ React แสดงข้อความเป็น Text ปกติ ไม่มีการส่ง LINE อัตโนมัติ และไม่มีการสร้าง Google Sheet สาธารณะ

ระบบนี้ยังไม่มีระบบยืนยันตัวตน ชื่อผู้ยืนยันเป็นการระบุเอง เหมาะกับการทดลองและการใช้งานบนเครื่องที่เชื่อถือได้ การนำไปเปิดหลายคนผ่านเครือข่ายต้องให้ IT เพิ่ม Login/สิทธิ์/HTTPS/การจัดการ Secrets ก่อน
