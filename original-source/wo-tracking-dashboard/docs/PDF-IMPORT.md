# อัปโหลด Packing List PDF

ใช้ PDF เพื่อสร้าง Invoice และรายการที่ต้องติดตาม แล้วนำผล QC และ WO จาก Google Sheets / CSV / Excel มาอัปเดตภายหลัง ไม่ต้องแปลง PL เป็น Excel ก่อน

## วิธีทดลอง

1. รัน `npm install` และ `npm run dev` แล้วเปิด http://localhost:5173
2. เลือกโหมด Demo และเมนู **นำเข้าข้อมูล**
3. ในกรอบ **อัปโหลด Packing List PDF** กด **เลือกไฟล์ PDF** แล้วเลือก `sample-data/packing-list-demo.pdf` เป็นข้อมูลสมมติ 2 หน้า 4 รายการ
4. ตรวจเลข Invoice, วันที่, SAP NO., Description และ SAP PO. แก้ไขช่องที่อ่านผิดได้เลย
5. ระบุวันที่รับของ / เริ่มรอ QC ถ้ามีหลักฐานวันที่จริง เพื่อให้ระบบคำนวณวันรอได้
6. กด **เปิดดู PDF ต้นฉบับ / ข้อความที่อ่านได้** เพื่อตรวจเทียบ หน้าจอเปิด PDF ที่เลือกบนเครื่อง ถ้าเบราว์เซอร์ไม่แสดงให้เปิดไฟล์จากเครื่องแยกต่างหาก
7. ตรวจจำนวนและทุกรายการ เพิ่มแถวที่ตกหล่น ลบแถวเกิน กรอกข้อมูลที่ยังขาด ตารางแก้ไขแบ่งหน้า 20 แถว
8. ติ๊ก **ตรวจจำนวนรายการและทุกแถวเทียบ PDF แล้ว** แล้วกด **ตรวจข้อมูลและ Preview ก่อนบันทึก**
9. ถ้าพบข้อผิดพลาด ให้กลับไปแก้ตารางและติ๊กตรวจใหม่ การแก้ร่างจะยกเลิก Preview เดิมเสมอ
10. เมื่อผ่าน กด **ยืนยันนำเข้าทั้งหมด** ด้านล่าง ข้อมูลจะบันทึกลง SQLite และปรากฏบน Dashboard หยุด/เปิดโปรแกรมใหม่ข้อมูลที่ยืนยันแล้วยังอยู่

การเลือก PDF หรือกด Preview ยังไม่บันทึกข้อมูล หากเปลี่ยนหน้า เปลี่ยนโหมด หรือ Refresh เบราว์เซอร์ ร่างในหน้าจอจะหาย Token มีอายุ 20 นาทีและหายเมื่อ Restart Backend ให้เลือกไฟล์ใหม่เมื่อหมดอายุ

## Ref. สำคัญอย่างไร

ระบบใช้ **Invoice + Ref. (item_ref)** จับคู่รายการ ห้ามจับคู่จาก SAP NO. อย่างเดียว เพราะ SAP NO. อาจซ้ำในหลาย Invoice หรือใน Invoice เดียวกัน

- หาก PDF มี ITEM NO. / LINE NO. ระบบใช้ค่าที่อ่านได้ เช่น `001` โดยเก็บเลขศูนย์นำหน้า
- หากไม่พบ ระบบตั้ง Ref. เริ่มต้นเป็น `PDF-รหัสสินค้า` ให้ตรวจและแก้ให้ตรงกับ `item_ref` ที่ฝ่าย QC/WO ใช้ใน Google Sheets
- ถ้า PDF มี `001` แต่ Sheets ใช้ `L001` ให้แก้ Ref. ในร่างเป็น `L001` ก่อนยืนยัน เพื่อให้ผล QC มาอัปเดตรายการเดียวกัน
- ถ้าในระบบมี SAP NO. เดียวกันใน Invoice เดียวกัน แต่ Ref. ไม่ตรง ระบบจะบล็อก PDF พร้อมแจ้ง Ref. เดิม ให้แก้ Ref. เพื่อจับคู่ หากเป็นคนละบรรทัดจริงจึงติ๊ก **รายการแยก** ในแถวนั้น ไม่ควรติ๊กเพื่อข้ามข้อผิดพลาดโดยไม่ตรวจ
- Ref. เดิมที่ผูกกับ SAP NO. อื่นแล้วจะเปลี่ยนสินค้าไม่ได้

## เมื่อนำเข้า PDF ซ้ำ

ถ้า Invoice + Ref. ตรงของเดิม ระบบคงผล QC, เลข WO, หลักฐาน, วันที่เดิม, หมายเหตุที่พนักงานบันทึก และประวัติไว้ ไม่ล้างด้วยช่องว่างใน PL นำเข้าไฟล์เดิมไม่เพิ่มรายการซ้ำ

Invoice ที่มีอยู่แล้วจะคงกำหนดการและผู้รับผิดชอบเดิม การเปลี่ยนข้อมูลเหล่านี้ให้ใช้ต้นทาง Sheets / CSV / XLSX เต็มแถวตามเดิม ส่วน Description ที่แก้ในร่าง PDF จะอัปเดตได้ หากมีการยืนยันเดิมและต้นทางเปลี่ยน ระบบจะแจ้งให้ตรวจการยืนยันใหม่ตามกฎเดิม

ข้อมูลใหม่ที่มาจาก PDF จะเริ่มเป็น **รอผล QC** ไม่เดา ACCEPT / REJECT / DIRECT ไม่สร้างเลข WO และไม่อ้างว่าเปิด WO แล้ว SAP PO. เก็บในหมายเหตุต้นทางของรายการใหม่ ดูได้เมื่อกด SAP NO. ไฟล์ PDF ต้นฉบับไม่ถูกเก็บหลังจบการนำเข้า จึงควรเก็บต้นฉบับไว้ในพื้นที่เอกสารของบริษัทตามเดิม

## ขอบเขตการอ่าน

- ขนาดไม่เกิน **10 MB / 50 หน้า / 1,000 รายการ** ต่อครั้ง อ่านแต่ละครั้งไม่เกิน 30 วินาที
- อ่าน Text PDF ที่เลือกคัดลอกข้อความได้ โดยรู้จักหัวตาราง SAP NO. และ DESCRIPTION พร้อม SAP PO. / ITEM NO. ที่มีอยู่ รองรับหัวตารางซ้ำหลายหน้าและ Description ต่อบรรทัดในรูปแบบที่ตรวจพบ
- หากอ่านหัวตารางไม่ได้ ไม่เดารหัสจากตัวเลขอื่นในเอกสาร แต่ให้เพิ่มและกรอกแถวเอง
- ภาพสแกนและหน้าที่ไม่มีชั้นข้อความยังไม่มี OCR อ่านอัตโนมัติ สามารถอัปโหลด เปิดต้นฉบับ แล้วกรอกในตารางเองได้
- อาจอ่านตกหล่นในตารางที่รูปแบบต่างจากตัวอย่าง ทุกครั้งต้องเทียบจำนวนรายการและทุกแถวกับต้นฉบับก่อนยืนยัน ไม่ควรใช้จำนวนที่อ่านได้เป็นหลักฐานว่าเอกสารถูกอ่านครบ
- Invoice หลายใบในไฟล์เดียวควรแยก PDF แล้วนำเข้าทีละ Invoice
- PDF ที่มีรหัสผ่านต้องปลดรหัสก่อน ไฟล์เสียหรือไฟล์ชนิดอื่นที่เปลี่ยนนามสกุลเป็น .pdf จะถูกปฏิเสธ
- ประมวลผลบนเครื่องด้วย PDF.js ไม่เรียก Gemini หรือบริการ OCR ภายนอก

## โค้ดที่เพิ่ม

| ไฟล์ | หน้าที่ |
|---|---|
| backend/src/pdf-extract.js | ตรวจ PDF อ่านข้อความ/ตำแหน่งใน Worker และจับข้อมูลตาราง |
| backend/src/pdf-import.js | ตรวจร่าง รักษา QC/WO เดิม และเตรียมเข้า Preview |
| frontend/src/PDFImport.jsx | ส่วนอัปโหลด เปิดต้นฉบับ แก้ไข และรับการตรวจจากผู้ใช้ |
| backend/test/pdf.test.js | ทดสอบ PDF จริงและเส้นทาง API/ฐานข้อมูล |
| frontend/src/PDFImport.test.jsx | ทดสอบขั้นตอนแก้ไข ตรวจ และยกเลิก Preview เก่า |

API เพิ่ม: `POST /api/import/pdf/extract` รับไฟล์ PDF และ `POST /api/import/pdf/preview` รับร่างที่ตรวจแล้ว จากนั้นใช้ `POST /api/import/commit` เดิมเพื่อบันทึก
