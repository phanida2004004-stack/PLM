# PLM Integrated — PL Brand System + QC / WO Tracking

ชุดรวมใหม่จาก ZIP ต้นฉบับทั้งสองชุด ใช้งานบนเครื่อง เปิดจาก URL เดียว และคงระบบ PL เดิมไว้

## เปิดใน VS Code (Mac / Windows)

1. แตก ZIP เป็นโฟลเดอร์ใหม่ชื่อ `PLM-Integrated` อย่าทับโปรเจกต์เก่า
2. เปิด VS Code → File → Open Folder → เลือก **PLM-Integrated ที่เห็น package.json และ server.mjs อยู่ข้างในทันที**
3. ใช้ Node.js **24 ขึ้นไป** ตรวจด้วย `node -v` (WO ใช้ SQLite ที่มาพร้อม Node)
4. เลือก Terminal → New Terminal แล้วรันทีละคำสั่ง:

```sh
npm ci
npm run doctor
npm run dev
```

5. เปิด **http://localhost:3000** สำหรับ QC / WO หรือ **http://localhost:3000/pl/** สำหรับอ่าน PL / หาแบรนด์
6. ปล่อย Terminal เปิดไว้ หากหยุดระบบให้กด **Control + C** (Mac ก็กด Control ไม่ใช่ Command)

มีหน้าเว็บที่สร้างไว้แล้ว ไม่ต้องเปิด port 5173 ไม่ต้องติดตั้ง Python และไม่ต้องมี API Key สำหรับอ่าน Text PDF / BOM / บันทึก / Print
ครั้งแรกที่ `npm ci` ต้องใช้อินเทอร์เน็ตเพื่อติดตั้งแพ็กเกจ; หน้าเว็บและตัวอ่าน Local ทำงานบนเครื่องหลังติดตั้งแล้ว

## ข้อมูลที่มีอยู่ในชุดนี้

- BOM เดิม 2,141 แถว, ฐาน BOM ใหม่ 2,448 BOM / 4,571 รหัส Component
- Production Model 4,251 แถว
- SAP Memory เดิม **166 รหัส**
- เอกสาร PL ที่ยืนยันแล้ว **9 ใบ / 346 รายการ** พร้อม PDF ที่อ้างอิงครบทั้ง 9 ใบ
- PDF ใน uploads ทั้งหมด **11 ไฟล์** คงเนื้อหาไฟล์เดิมทุกไบต์
- ข้อมูลตัวอย่าง WO แยกจากข้อมูลจริง

**ZIP ต้นฉบับ WO ไม่มีฐานข้อมูล QC/WO จริงหรือ Google Credentials มาให้** ดังนั้นหน้าติดตามข้อมูลจริงจะเริ่มว่าง ข้อมูล PL เดิมทั้ง 9 ใบยังอยู่ที่หน้า PL / ประวัติเอกสาร สามารถเลือกเข้ามาติดตามได้ในหน้า “นำเข้าข้อมูล”

รายการเครื่องมือบางแถวใน PL ต้นฉบับไม่มี SAP NO. ระบบเก็บไว้ตามเดิม การนำเข้า WO จะขอให้ตรวจและระบุรหัสจริง หรือเอาแถวที่ไม่ติดตาม WO ออกจากร่างก่อน Preview; ไม่ลบข้อมูลใน PL เดิม

## การใช้สองระบบร่วมกัน

1. กด **PL Brand System** → อัปโหลด PDF หรือเปิดเอกสารเดิม
2. ตรวจ SAP PO / SAP NO. / Description / BOM / Brand / Production Model
3. ทำเครื่องหมายในช่องใต้เลขแถวให้ครบทุกแถว แล้วกด **ยืนยันข้อมูล**
4. กลับ **QC / WO Tracking** → **นำเข้าข้อมูล** → เลือกเอกสาร PL ที่ยืนยันแล้ว → **ใช้รายการจาก PL**
5. กรอกวันรับของ/ผู้รับผิดชอบ ตรวจ Ref. ให้ตรงกับ `item_ref` ใน Google Sheets แล้ว Preview / ยืนยันนำเข้า
6. นำเข้าผล QC / WO จาก Google Sheets, CSV หรือ XLSX ภายหลังด้วย **Invoice + item_ref เดิม**

ระบบจะไม่สร้างผล QC หรือเลข WO จาก Brand/Production Model และไม่อ้างว่าอ่าน SAP แบบ real-time
กฎ QC เดิม: ACCEPT → STK+CTN_CHANGE CODE, REJECT → Inspection_Assembly, DIRECT → ต้องมีผู้ยืนยันและหลักฐาน

## การอ่าน PDF และ AI

ค่าเริ่มต้น `PL_READER=local` ใช้ตัวอ่านพิกัดตารางจากระบบ PL เดิม และ OCR บนเครื่องสำหรับภาพสแกนในหน้า PL
Text PDF ตัวอย่างเดิมทั้ง 4 ชุดผ่านการเทียบจำนวนแถวและข้อมูล 9 ช่อง ภาพสแกนหรือรูปแบบ PDF อื่นอาจอ่านผิด/ไม่ครบ ต้องตรวจต้นฉบับก่อนยืนยัน
หน้า WO รับ PDF โดยใช้ตัวอ่าน PL เดียวกันก่อน และมีร่างแก้ไขได้ หากต้องการเก็บ PDF ต้นฉบับในประวัติ ให้เริ่มจากหน้า PL แล้วเลือกเอกสารที่ยืนยันแล้วมาใช้

หากต้องการ AI ให้คัดลอก `.env.example` เป็น `.env` ตั้ง `PL_READER=ai`, `GEMINI_API_KEY` และ `GEMINI_MODEL` ที่บัญชีใช้งานได้ แล้วเริ่ม Server ใหม่ การใช้ AI จะส่ง PDF ให้ Gemini ตามการตั้งค่านี้ และขึ้นกับสิทธิ์/โควตาของบัญชี
ชุดนี้ทดสอบ Local โดยไม่เรียก Gemini และไม่ส่งเอกสารบริษัทออกไประหว่างการทดสอบ

## Brand และข้อมูลที่เคยยืนยัน

ค้นหาได้ทั้ง BOM หลักและ Component ย้อนกลับ พร้อมใช้ SAP Memory ที่ยืนยันแล้ว (รายการ CONFIRMED ต้องตรง SAP PO)
ใช้แบรนด์ที่มีหลักฐานใน SAP PO เดียวกันเป็นหลัก; หากหลักฐานขัดกันและยังไม่มีข้อมูลยืนยันที่ชัดเจน ให้ Conflict และผู้ใช้ตรวจเอง ไม่มีการเลือกจากเสียงข้างมาก
รายการไม่มี BOM จะไม่แสดง Brand/Production Model และไม่เดา Brand
การยืนยันบันทึกทั้งเอกสารและ SAP Memory แบบมีไฟล์กู้คืน หากข้อมูล JSON เสีย ระบบหยุดการเขียนแทนการเขียนทับข้อมูลเดิมด้วยรายการว่าง

## Print

กด Print Preview หลังยืนยัน จะเก็บขนาดหน้าและเนื้อหา PDF ต้นฉบับ พร้อมเพิ่ม BOM / BRAND ด้านขวา **ไม่มี Production Model และไม่มีสีเทาที่ระบบเติมให้**
สีหรือไฮไลต์ที่มีอยู่แล้วใน PDF ต้นฉบับยังคงอยู่ รองรับ Print เอกสารเดิมทั้ง 9 ใบ รวมหน้าต่อที่มีเฉพาะน้ำหนัก/ขนาด
หาก SAP NO. ที่แก้แล้วจับคู่กับต้นฉบับไม่ได้ ระบบแจ้งให้ตรวจ ไม่เติม Brand ลงแถวอื่นแทน

## แก้/สำรองข้อมูล

- ฐาน BOM/Model/Memory: `pl/sample-data/`
- PDF และประวัติเอกสาร: `pl/uploads/`
- ข้อมูล QC/WO จริง: `database/real.sqlite` (สร้างเมื่อรันครั้งแรก)
- ข้อมูล Demo: `database/demo.sqlite`
- ต้นฉบับก่อนแก้ของทั้งสองโปรเจกต์: `original-source/` (เก็บทุกไฟล์ที่เป็นงานจริง ไม่รวม .git, node_modules, __MACOSX และ .DS_Store)
- แก้ CSV ต้องคงชื่อและหัวคอลัมน์เดิม แล้วหยุด/เริ่ม Server ใหม่
- **ควรหยุด Server ก่อนสำรอง** แล้วรัน `npm run backup` จะเก็บ WO + PDF + PL + Memory ใน `backups/`
- อย่าลบ `pl/uploads/`, `pl/sample-data/`, `database/` หรือย้ายเฉพาะ Source Code ไปใช้ เพราะโฟลเดอร์เหล่านี้มีข้อมูลที่ใช้งานจริง

## คำสั่งและการแก้ปัญหา

| คำสั่ง | หน้าที่ |
| --- | --- |
| `npm run dev` / `npm start` | เปิดทั้งสองระบบที่ port เดียว |
| `npm run doctor` | ตรวจ Node, แพ็กเกจ, ข้อมูลและ PDF ที่อ้างอิง |
| `npm test` | ทดสอบกฎ QC, นำเข้า, PL, การบันทึก, Print และหน้าเว็บ |
| `npm run build` | สร้างหน้าเว็บหลังแก้ UI; มีไฟล์ที่สร้างไว้แล้วใน ZIP |
| `npm run check` | ตรวจไฟล์/ภาษา JavaScript และ Build |
| `npm run backup` | สำรองข้อมูลทั้งสองระบบ |

- **Missing script: dev**: เปิดผิดโฟลเดอร์ ต้องเห็น package.json ชื่อ `plm-integrated` ในโฟลเดอร์เดียวกับ Terminal
- **Port 3000 ถูกใช้งาน**: กด Control+C ที่ Terminal ของระบบเก่า แล้วรันใหม่
- **node:sqlite ไม่พบ**: เปลี่ยนเป็น Node 24 ขึ้นไป แล้วเปิด Terminal ใหม่
- **localhost เข้าไม่ได้**: ดู Terminal ว่า Server ยังรันอยู่ และใช้ URL ที่แสดง ถ้าเปลี่ยน PORT ใน .env ต้องใช้ port นั้น
- **หน้าติดตามว่าง**: ตรวจว่าอยู่โหมดข้อมูลจริงหรือ Demo; PL เดิมไม่ได้ถูกตีความเป็นผล QC/WO อัตโนมัติ
- **แก้หน้าตาแล้วไม่เปลี่ยน**: รัน npm run build แล้วรีเฟรช
- **Google Sheets**: ต้องมีบัญชี Service Account ของบริษัทและสิทธิ์ Viewer ตาม `docs/GOOGLE-SHEETS.md`; ไม่มี Credentials ส่วนตัวอยู่ใน ZIP

ระบบผูกกับ localhost เท่านั้น ไม่ได้เผยแพร่เว็บหรือเปิดให้บุคคลภายนอกเข้าถึง
