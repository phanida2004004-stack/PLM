# คู่มือนำเข้า CSV / XLSX

การอัปโหลด Packing List PDF ใช้กรอบบนสุดในหน้าเดียวกัน ดูขั้นตอนใน [PDF-IMPORT.md](PDF-IMPORT.md) ส่วนคู่มือนี้ใช้กับผล QC และ WO ตามแม่แบบ 22 คอลัมน์

## ขั้นตอน

1. เริ่มโหมด Demo เพื่อทดลอง และเปลี่ยนเป็นข้อมูลจริงเมื่อต้องใช้ข้อมูลบริษัท
2. เมนูนำเข้าข้อมูล > ดาวน์โหลดแม่แบบ หรือใช้ไฟล์ sample-data/template.csv ซึ่งมีหัวคอลัมน์ครบแต่ไม่มีข้อมูล
3. XLSX กรอกใน Tracking เท่านั้น ลบแถวตัวอย่างก่อนใช้ข้อมูลจริง CSV ต้องเป็น UTF-8 (Excel: CSV UTF-8) รองรับ UTF-8 BOM
4. คงหัวคอลัมน์ทั้ง 22 ช่อง แม้ไม่มีข้อมูลในบางช่อง ให้เว้นว่าง ไม่ใส่เครื่องหมาย - แทนวันที่และเลข WO
5. เลือกไฟล์ ดู Preview (แสดงสูงสุด 100 รายการแรก) และอ่านข้อผิดพลาด/ข้อสังเกตของทั้งชุด
6. ข้อผิดพลาดต้องแก้ในไฟล์แล้ว Preview ใหม่ ข้อสังเกตเป็นข้อมูลที่นำเข้าได้แต่ควรตรวจต่อ
7. เมื่อกดยืนยัน ระบบจะนำเข้าทั้งชุดใน Transaction เดียว หากล้มเหลวจะไม่บันทึกค้างเพียงครึ่งชุด

CSV/XLSX สูงสุด 10 MB และ 10,000 แถวต่อครั้ง ข้อมูล XML ภายใน XLSX สูงสุด 40 MB ไม่อ่าน Macro และไม่รองรับไฟล์ .xls หรือไฟล์ที่ติดรหัสผ่าน ต้องใช้ค่าจริงในเซลล์ ไม่ใช้สูตรหรือ Rich Text สำหรับช่องนำเข้า

## คอลัมน์

| ชื่อ | ความหมาย / วิธีกรอก |
|---|---|
| invoice_no | จำเป็น เลข Invoice |
| item_ref | จำเป็น รหัสรายการคงเดิมภายใน Invoice เช่น L001 หรือรหัสบรรทัดจากต้นทาง |
| sap_no | จำเป็น รหัสสินค้า เก็บเป็นข้อความ |
| description | จำเป็น รายละเอียดสินค้า |
| invoice_date | วันที่ Invoice ไม่มีเว้นว่าง |
| etd / eta / etr | วันที่ตามเอกสาร ไม่มีเว้นว่าง |
| owner | ผู้รับผิดชอบ ไม่มีเว้นว่าง |
| received_date | วันที่รับสินค้า / เริ่มรอผล QC |
| qc_result | ACCEPT, REJECT, DIRECT หรือข้อความ QC ที่ชัดเจน ไม่มีเว้นว่าง |
| qc_date | วันที่รับผล QC / ยืนยัน DIRECT ใช้เป็นวันเริ่มรอเปิด WO |
| direct_confirmed | TRUE เมื่อผู้รับผิดชอบยืนยัน DIRECT จริง ไม่เช่นนั้น FALSE |
| direct_by | ผู้รับผิดชอบที่ยืนยัน DIRECT |
| qc_reference | ข้อมูลอ้างอิงผล QC หรือการยืนยัน DIRECT เช่น เลขข้อความ/วันที่ |
| wo_number | เลข WO ที่เปิดจริง ห้ามกรอกค่า OPEN / DONE แทนเลข |
| wo_model | Model ของ WO ที่พบจริง ไม่ใช่ Model ที่คาดว่าจะเปิด |
| wo_verified | TRUE เฉพาะเมื่อตรวจหลักฐานแล้วว่าจับคู่กับรายการนี้จริง |
| wo_date | วันที่เปิด WO |
| wo_by | ผู้เปิด WO |
| wo_reference | หลักฐาน WO เช่น ชื่อไฟล์ SAP Export และวันที่ |
| source_note | หมายเหตุต้นทาง แยกจากหมายเหตุที่พนักงานบันทึกในเว็บ |

วันที่ใช้ YYYY-MM-DD เช่น 2026-10-21 รองรับ DD/MM/YYYY และปี พ.ศ. 2569 ด้วย ห้ามใช้เดือน/วัน/ปีสองหลัก หรือวันที่เช่น 31/02/2026 ซึ่งไม่มีอยู่จริง ระบบแสดงวันที่เป็นปี ค.ศ. ค่า TRUE/FALSE รองรับ 1/0 และ yes/no ด้วย

## รหัสรายการและการอัปเดต

- Invoice + item_ref เป็นตัวระบุคงที่ ห้ามสร้าง item_ref ใหม่จากเลขแถวปัจจุบันทุกครั้ง เพราะการเรียงแถวใหม่อาจทำให้จับคู่ผิด
- SAP NO. ซ้ำคนละ Invoice ได้ และซ้ำใน Invoice เดียวกันได้ถ้า item_ref ต่างกัน
- ถ้าสินค้าหนึ่งต้องติดตามหลาย WO Model ให้แยกเป็นคนละรายการอ้างอิง เช่น L001-INS กับ L001-DIR โดยมีหลักฐานของแต่ละรายการจริง ยอดการ์ดนับเป็นรายการติดตาม ไม่ใช่จำนวน SAP NO. ที่ไม่ซ้ำ
- ระบบไม่จับ WO ข้ามแถวด้วย SAP NO. เพียงตัวเดียว WO ในไฟล์ต้องถูกจัดเข้ากับ Invoice / item_ref โดยต้นทางหรือผู้ตรวจหลักฐานก่อน
- WO Number เดียวกันถูกใช้กับหลายรายการ ระบบจะบล็อกเพื่อตรวจสอบ หากบริษัทใช้ WO หนึ่งเลขครอบคลุมหลายบรรทัดจริง ต้องปรับข้อตกลงข้อมูลก่อนใช้กรณีนั้น
- แถวซ้ำตรงกันทุกช่องในไฟล์เดียวกันจะข้ามแถวซ้ำ แถวที่รหัสซ้ำแต่ข้อมูลต่างกันจะถูกบล็อก
- นำเข้าซ้ำทั้งไฟล์เดิมจะไม่สร้างรายการเพิ่ม และไม่บันทึกประวัติเปลี่ยนแปลงรายสินค้าซ้ำโดยไม่จำเป็น แต่มีประวัตินำเข้าแต่ละครั้ง
- เปลี่ยนข้อมูลภายใต้ Invoice + item_ref เดิมจะอัปเดตค่าต้นทางทั้งแถว รวมถึงค่าที่เว้นว่าง ควรส่งแถวเต็มที่เป็นสถานะล่าสุดเสมอ
- เปลี่ยน SAP NO. ของ item_ref เดิมจะถูกบล็อก เพื่อป้องกันการนำประวัติคนละสินค้ามารวมกัน ให้แก้ต้นทางหรือใช้รหัสอ้างอิงใหม่ที่ถูกต้อง
- รายการที่หายไปจากไฟล์จะไม่ถูกลบอัตโนมัติ ระบบใช้วิธี Upsert (เพิ่มเมื่อใหม่ / อัปเดตเมื่อพบรหัสเดิม)
- หมายเหตุในเว็บยังอยู่ การยืนยันด้วยคนยังถูกเก็บไว้ แต่ถ้าข้อมูลต้นทางเปลี่ยนหลังยืนยัน จะเป็นต้องตรวจสอบจนกว่าจะตรวจและยืนยันใหม่
- หลัง Preview ถ้ามีการเปลี่ยนค่าต้นทางของรายการเดียวกันก่อนกดยืนยัน ระบบจะให้ Preview ใหม่

ไฟล์ทดสอบ: demo.csv มี 25 รายการ, duplicate-identical.csv มีแถวซ้ำเหมือนกัน และ invalid-duplicate.csv มีรหัสซ้ำขัดแย้งพร้อมข้อมูลที่ขาด
