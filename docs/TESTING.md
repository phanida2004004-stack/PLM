# คู่มือทดสอบระบบ

## อัตโนมัติ

หลัง npm install ให้รัน `npm test` และ `npm run check` จาก Terminal ในโฟลเดอร์หลัก คำสั่ง test ใช้ฐานข้อมูลชั่วคราวสำหรับ Backend จึงไม่แก้ข้อมูลจริง Frontend ทดสอบด้วย React Testing Library + jsdom ไม่ใช่เบราว์เซอร์จริง

`npm run smoke` เปิด Server จริงด้วยพอร์ตว่างชั่วคราว ตรวจหน้าเว็บและไฟล์ JavaScript ผ่าน HTTP บันทึกหมายเหตุทดสอบลง **Demo** ปิด/เปิด Server ใหม่ ตรวจหมายเหตุยังอยู่ และสำรองฐานข้อมูลทั้งสองโหมด ไม่เปิดหน้าต่างเบราว์เซอร์ คำสั่งนี้ตั้งใจใช้กับ Demo เริ่มต้น 25 รายการ หากคุณเพิ่ม/ลด Demo เองแล้ว ยอดอาจไม่ตรงเงื่อนไขทดสอบ ไม่ควรใช้คำสั่งนี้แทนการตรวจข้อมูลจริง

| ค้นหา SAP NO. และกรองสถานะในตาราง | เหลือเฉพาะรายการที่ตรงและเลขหน้าเริ่มที่ 1 |
| กด SAP NO. | เปิด Drawer ที่มี Invoice + item_ref ตรงกับแถวที่กด |

| Import invalid-duplicate.csv | ข้อผิดพลาดและปุ่มยืนยันใช้ไม่ได้ |
| Import google-sheets-template.xlsx ใน Demo | อ่านข้อมูลตัวอย่าง 4 แถว วันที่ถูกต้อง |
| Import ข้อมูล INV-DEMO ในโหมดข้อมูลจริง | ระบบบล็อกและอธิบายว่าเป็นข้อมูลสมมติ |
| Copy ข้อความ LINE | ลองวางในช่องข้อความว่าง เห็น Invoice/SAP/Ref และสิ่งที่ต้องติดตาม ไม่มีการส่งเอง |
| ส่งออก Excel | เปิดไฟล์ใน Excel/Google Sheets ตรวจตรงสถานะ/ช่วงวันที่/คำค้น |
| เปลี่ยนเป็นข้อมูลจริงครั้งแรก | ว่าง ไม่มีข้อมูลสมมติปน |
| Restart Server | หมายเหตุและการยืนยันที่บันทึกก่อนปิดยังอยู่ |

การแก้ใน Demo จะทำให้ยอดเปลี่ยนตามจริง ไม่ต้องพยายามแก้กลับให้ได้ตัวเลขตั้งต้นเพื่อใช้ทำงาน

## ข้อมูลต้นทางเปลี่ยน

ยืนยันแถวหนึ่งใน Demo > ทำสำเนา demo.csv > เปลี่ยนผล QC แถวนั้น > นำเข้าสำเนา > ตรวจว่ามีป้ายต้องตรวจสอบและการยืนยันเดิมยังดูได้ในประวัติ > เปิด Drawer ตรวจหลักฐานและยืนยันใหม่ จากนั้นตรวจว่ายอดกลับไปตามข้อมูลที่ยืนยัน

## ตรวจ Responsive บนเครื่องผู้ใช้

เปิด Chrome > Developer Tools > Device toolbar แล้วตรวจขนาด 1440×900, 1024×768, 768×1024 และ 390×844 ให้การ์ดไม่ซ้อน เมนูยังเปิดได้ ช่องค้นหาไม่ถูกตัด และตารางเลื่อนไปด้านข้างได้ กด Tab เพื่อดูขอบโฟกัส กด Escape เพื่อปิด Drawer

จุดนี้ต้องตรวจภาพจริงบนเบราว์เซอร์ของผู้ใช้เพิ่มเติม ไม่ได้ผ่านจาก jsdom เพียงอย่างเดียว

## หลังเชื่อม Google Sheets ที่ได้รับอนุญาต

1. ใช้ Spreadsheet ทดสอบส่วนตัวขององค์กรที่แชร์เฉพาะ Service Account และผู้เกี่ยวข้อง ใส่ข้อมูลสมมติที่ใช้รหัสทดสอบใหม่ (ไม่ใช้ INV-DEMO ในโหมดจริง)
2. ดึง Preview > ยืนยัน > ตรวจรายการ Invoice, ผล QC, WO Model, หลักฐาน และเวลานำเข้าสำเร็จ
3. แก้แถวเดิมในชีตแล้วรีเฟรช ตรวจการอัปเดตและประวัติ
4. บันทึกหมายเหตุในเว็บแล้วรีเฟรชชีต หมายเหตุต้องไม่หาย
5. เพิกถอนสิทธิ์ Service Account ชั่วคราวในชีตทดสอบ แล้วดึงอีกครั้ง ต้องเห็น Error และข้อมูลที่บันทึกไว้ยังอยู่ จากนั้นคืนสิทธิ์ตามที่ได้รับอนุญาต
6. ตรวจเทียบรายการตัวอย่างกับ SAP Export ที่ผู้รับผิดชอบรับรอง ก่อนใช้ข้อมูลบริษัทจริง

ห้ามใช้ผลทดสอบโหมด Demo แทนการยืนยันความถูกต้องของข้อมูลบริษัท
